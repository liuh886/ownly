# Ownly 近期优化落地与代码质量检查（2026-10-03）

## 结论与范围

近期优化已进入实际代码及测试，不能仅凭此前的“全部通过”记录认定质量闭环完成。本轮发现并修复了演示存储隔离、模式切换、读失败处理、零金额计算和依赖审计门禁的问题。

检查基于 `c9809bf`（main）与本地工作区；重点回看 2026-09-18 至 2026-10-02 的改动、`tasks/todo.md` 和产品 spec。开始时已有 7 个修改文件和 2 个未跟踪测试；它们被保留并纳入验证。测试使用内存仓库、临时目录及本地静态产物，没有访问真实个人数据目录。本轮未发布站点，也未修改 Supabase 或 Obsidian 测试 Vault。

## 剩余风险与质量判断

- 生产依赖的最终官方 npm 审计为 **0 漏洞**。完整依赖树仍有 **5 high + 5 moderate** 包条目，属于开发工具链；条目数不是独立漏洞数。high 链为 `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`；moderate 涉及 Vitest mocker 和 Obsidian/moment。审计建议含降级 Next lint 配置至 14.x、降级 Obsidian 或升级 Vitest 大版本，不能直接执行 `audit fix --force`。需独立完成兼容性验证。仓库 `.github/ci-policy.json` 将开发工具风险列为 advisory，此次如实保留该未完成项。
- 原生 File System Access 权限弹窗、目录移动/失效的真实浏览器行为、iPhone 分享查看仍缺少本轮真机验收；受控测试不能替代这些检查。
- 示例快照固定到 2026-08，行程固定到 2026-11/12 和 2027-01；目前三份行程仍在未来，2027-01 后需要内容更新。`check:sample-dates` 是报告工具，并非阻断门禁。
- `/app/` 首载 JS gzip 为 362.5 KB，预算 363.3 KB，余量仅约 0.8 KB；门禁虽通过，后续界面新增需优先拆包，避免继续上调预算。
- 中文城市搜索数据重生成、真实新用户的引导理解测试仍是既有未竟事项；本轮没有将它们标为已落地。
- 代码整体已有较好的 domain/service 分层、schema 契约与 CLI/MCP parity。主要缺口是数据模式变更的交互与异步边界缺少行为测试，本轮补充了这些保护；远端部署和原生交互不在“单元测试全部通过”的结论范围内。
