# 旅行、Planner 与复盘的统一关系

一趟旅行由一个旅行经历对象、一个 Planner 行程和关联该对象的复盘组成。

- `PlannerTrip.experience_id` 是从规划阶段开始的稳定关联，指向物欲中的 `one_time_experience` 对象。
- 旧 `review_id` 实际指向经历对象，并非 ReviewEntry；读取时兼容，保存时补上 `experience_id`。两个字段同时存在时必须指向同一个对象。
- 复盘仍使用 `ReviewEntry.target_id` 指向该旅行对象，`review_ref` 指向当前复盘。Planner 按此关系读取评分，不另存一份评分。

## 用户入口

物欲中的旅行有“行程规划”入口：已经关联的直接打开行程；尚未关联的打开预填表单，补齐日期后创建。

Planner 新建行程时可以选择已有旅行，也可以创建对应旅行经历。旧的未关联行程可以在行程管理的编辑表单中明确选择已有旅行。同名不会自动合并；一个经历不能同时关联两个行程，已经建立的关联不能通过普通编辑更换。

Planner 完结、重新打开、修改名称、日期、目的地和状态会更新关联对象；物欲中修改同一旅行的这些字段也会更新行程。目的地沿用已有的国家代码、经纬度等详情。物欲拥有预算、原始笔记与扩展字段；Planner 不覆盖它们。

## 复盘与金额

有关联对象的行程复盘复用对象及现有 ReviewEntry，正文与评分在复盘页、Planner 编辑器中共用。文字复盘不强制评分。原始旅行笔记继续保存在对象中。

有完整汇率的账本总额在保存行程复盘时更新实际花费；没有记账或缺汇率时保留原先实际总额，避免以空值或部分折算覆盖用户记录。账本费用明细属于 Planner，物欲预算及手填明细继续保留。有金额的旅行不允许直接换币种并重标金额。

## 一致性和兼容

跨仓库写入绑定同一个工作区，Planner 与对象均使用写会话。失败时恢复原记录，新建记录的恢复通过归档保留。编辑器保存前检查原始快照，检测到其他入口的修改时阻止覆盖。

保存后通知应用重读对象及复盘；复盘页的目标定位支持首次挂载和异步数据到达。分享、导入复制行程时去掉 `experience_id` 与 `review_id`，防止引用分享者的私人对象。

不批量改写旧数据或仅凭名称归并历史重复记录。旧的自动生成经历继续使用原有 ID；关联记录缺失或已归档时提示先恢复记录。
