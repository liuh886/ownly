# Ownly Data Model

Ownly stores its source-of-truth records as plain `.md` files with YAML frontmatter inside an **Ownly data folder**.

The data folder may be:

- `Ownly/` inside an Obsidian Vault (recommended), or
- a standalone local Ownly folder used by the Web app or PWA without Obsidian.

Web, PWA, Obsidian, and the Agent CLI must use the same schemas, paths, lifecycle rules, and archive semantics.

## Directory structure

```text
Ownly/
  Objects/
  Accounts/
  Snapshots/
  Reviews/
  Trips/
  Trip Places/
  Trip Visits/
  Trip Legs/
  Trip Expenses/
  Logs/
    Object Experiences/
  Archive/
    Objects/
    Accounts/
    Snapshots/
    Reviews/
    Object Logs/
```

## Shared base fields

Every entity includes at least:

- `schema_version` (`'0.1'` for Planner entities)
- `id`
- `type`
- `created_at` (or `title`)

Optional shared fields include `updated_at`, `currency`, `tags`, and `notes`.

Archive metadata such as `archived_at`, `archived_from`, and `original_file_name` is added only to recoverable archived copies and removed when the record is restored.

## Entity types

### 1. Physical items

- Entity type: `object`
- Object type: `physical`
- Stable fields include `id`, `object_type`, `title`, `status`, `category`, purchase/use/exit dates, cost fields, condition, and location.
- Lifecycle statuses include `seeded`, `observing`, `purchased`, `using`, `idle`, `transferred`, and `discarded`.
- `physical_asset` is legacy-only and must not be generated by new tools.

### 2. Recurring costs

- Entity type: `object`
- Object type: `recurring_cost`
- Stable fields include `billing_amount`, `billing_cycle`, `billing_day`, `payment_account`, provider/plan details, and lifecycle dates.
- Statuses include `seeded`, `active`, `paused`, and `cancelled`.

“Subscription” is acceptable user-facing wording for a recurring cost, but `recurring_cost` remains the stable schema and CLI identifier.

### 3. One-time experiences

- Entity type: `object`
- Object type: `one_time_experience`
- Stable fields include plan/start/end/review dates, location data, budget, actual cost, expense items, and worldview tags.
- Statuses include `planned`, `in_progress`, `completed`, and `reviewed`.

### 4. Reviews

- Entity type: `review`
- Fields include `review_type`, `target_id`, `target_type`, review/exit dates, summary, rank fields, score fields, regret score, and realized experience cost where applicable.
- Objects and reviews may be linked bidirectionally through `review_ref` and `target_id`.

### 5. Object experience logs

- Entity type: `object_log`
- Path: `Ownly/Logs/Object Experiences/`
- Fields include `target_id`, `event_type`, `occurred_at`, `summary`, `lesson`, `source`, and `created_at`.
- Event types: `usage`, `issue`, `maintenance`, `regret`, `lesson`, `comparison`, and `exit_note`.
- Logs are append-only facts and do not silently mutate object lifecycle status.

### 6. Snapshots

- Entity type: `snapshot`
- Snapshot type: `net_worth`
- Fields include `snapshot_at`, asset and liability balances, totals, net worth, and optional ownership metrics.

### 7. Accounts

- Entity type: `account`
- Fields include account type, provider/name, status, net-worth inclusion, and asset or liability classification.
- Runtime support may differ temporarily; capability differences must be explicit rather than represented by a separate schema.

### 8. Travel Trips

- Entity type: `trip`
- Path: `Ownly/Trips/`
- Container for a multi-day itinerary.
- Stable fields include `id`, `title`, `status` (`planning`, `active`, `completed`), `start_date`, `end_date`, `destinations` (array of strings), `currency`, `members`, and `transport_mode`.

### 9. Travel Places

- Entity type: `trip_place`
- Path: `Ownly/Trip Places/`
- Reusable location entity referenced by multiple visits.
- Stable fields include `id`, `trip_id`, `title`, `kind` (`stay`, `attraction`, `food`, `shopping`, `transit`, `flight`, `other`), `priority` (`must`, `want`, `optional`), `state` (`candidate`, `done`, `dropped`), `source_provider`, `source_place_id`, `source_url`, `coordinates`, `open_hours`, `duration_minutes`, `observed_price`, `observed_rating`, `hotel_facts`, and `reservation_status`.

### 10. Travel Visits

- Entity type: `trip_visit`
- Path: `Ownly/Trip Visits/`
- Scheduling atom representing a concrete occurrence of a Place on a specific date.
- Stable fields include `id`, `place_id`, `trip_id`, `date`, `start_time`, `end_time`, `duration_minutes`, `sort_order`, `locked`, and `is_anchor`.

### 11. Travel Legs

- Entity type: `trip_leg`
- Path: `Ownly/Trip Legs/`
- Route segment connecting two adjacent Places on a given day.
- Stable fields include `id`, `trip_id`, `from_place_id`, `to_place_id`, `mode` (`driving`, `walking`, `motorcycle`, `cycling`, `transit`), `duration_minutes`, `distance_meters`, and `source` (`heuristic`, `manual`, `openrouteservice`).

### 12. Travel Expenses

- Entity type: `trip_expense`
- Path: `Ownly/Trip Expenses/`
- Group expense record tied to a trip date with multi-member payment split ledger.
- Stable fields include `id`, `trip_id`, `date`, `amount`, `currency`, `category`, `description`, `paid_by`, and `payments` (`member`, `amount`).

## Serialization rules

- Every record is self-contained YAML frontmatter plus an optional Markdown body.
- Required fields must be validated when records are parsed or written.
- Unknown forward-compatible fields should be preserved unless an explicit migration safely transforms them.
- Creating a same-day, same-title record must not overwrite an existing Markdown file.
- Archive writes must complete before the active source is removed.
- Archive and restore filename collisions must be resolved without silently overwriting valid data.
- Permanent deletion applies only to an explicitly selected archived record.

## Safe access for scripts and external agents

The Agent CLI is Ownly's deterministic fact-ready interface for scripts and external agents:

```bash
npm run wyqd -- --vault <path> object list --json
```

Agents should use documented CLI commands instead of editing frontmatter through unvalidated file manipulation. The CLI is responsible for schema checks, error codes, and stable JSON output.

Ownly does not provide AI chat, embeddings, model-generated recommendations, or a hidden AI data layer. It provides structured local facts that external tools may consume under user control.
